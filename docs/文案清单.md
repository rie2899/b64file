## 二、各页面内容文字

### 1. 首页 /

- **meta 标题**：Base64 转文件 · 文件转 Base64 · 在线编解码工具 - b64file
- **meta 描述**：免费 Base64 在线转换工具：Base64 转文件、文件转 Base64、文本编解码。自动修复 Data URL 前缀与填充符，浏览器本地处理，文件不上传。
- **H1**：Base64 转文件 · 文件转 Base64
- **首屏导语**：贴进来。纯 Base64、带前缀的 Data URL、甚至整段接口返回的 JSON——先自动体检，能修的都修了，修不了的告诉你坏在哪，最后把文件还给你。图片、PDF、压缩包都认识。文件不出浏览器：没有上传接口，想传也没地方传。
- **章节「怎么用：三步」**：
  1. 贴进来 — 粘贴、拖文件、Ctrl+V 截图，格式不挑
  2. 看体检报告 — 前缀、换行、缺失的填充符，能修的都替你修了；数据断了会明确告诉你
  3. 拿走文件 — 下载还原的文件，或复制编码结果
- **章节「为什么死磕本地处理」**（三张卡片，各带终端头）：
  - `no_upload` **没有上传接口**：不是"我们承诺不看你数据"，是技术上做不到——服务器只有静态页面，连接收文件的接口都不存在。
  - `instant` **粘贴的瞬间出结果**：不经网络往返，处理就在你设备上。你可以打开开发者工具的 Network 面板自己验证。
  - `magic_bytes` **认文件靠文件头**：不靠扩展名：%PDF 开头就是 PDF，改成 .exe 也骗不过它。20 多种格式开箱即认。
- **FAQ**：
  - 支持哪些格式？→ PNG、JPEG、GIF、WebP、SVG、PDF、ZIP、GZIP、RAR、7Z、MP3、WAV、MP4 等二十多种，靠文件头魔数识别。不认识的内容也会给你原始二进制下载。
  - 文件会被传到哪吗？→ 哪也去不了。没有上传接口，服务器只发页面本身。不信的话，开着 Network 面板用一遍。
  - 最大能处理多大？→ 100 MB 封顶，超过 20 MB 会先跟你确认——大文件吃内存，别把你标签页搞崩了。
  - Base64 是加密吗？→ 不是，差得远。Base64 谁都能还原，别拿它保护密码。
  - 解码失败怎么办？→ 八成是非法字符、缺填充符或数据被截断。看解码失败排查指南，或者直接贴进来让工具告诉你坏在哪。

### 2. /base64-to-file/

- **meta 标题**：Base64 转文件在线工具 - 免费本地处理 - b64file
- **meta 描述**：粘贴 Base64 字符串，自动识别文件类型并还原为可下载文件。支持 data URL 前缀、Base64URL、缺失填充自动修复。本地处理不上传。
- **H1**：Base64 转文件在线工具
- **首屏导语**：粘贴 Base64，自动认出它是什么文件——看文件头，不看文件名。前缀、换行、缺填充符这些常见毛病能修的都替你修了，修不了的会告诉你数据断在哪。修好之后，一键下载。
- **章节「自动修复项」**：
  - Data URL 前缀 — data:image/png;base64, 开头自动去除
  - 换行与空格 — 邮件、终端复制带出的换行自动清理
  - Base64URL — - 和 _ 自动转为标准 + 和 /
  - 填充符 — 缺失的 = 自动补齐，多余的自动修正
- **章节「支持的文件类型」**：图片：PNG / JPEG / GIF / WebP / BMP / ICO / SVG；文档：PDF；压缩包：ZIP / GZIP / RAR / 7Z；音频：MP3 / WAV / OGG / FLAC；视频：MP4 / MOV / AVI；其他：EXE / ELF / SQLite，以及 UTF-8 纯文本。
- **章节「不知道原始文件名怎么办」**：工具通过文件头魔数判断类型，不依赖文件名或扩展名。下载时可自定义文件名，默认扩展名来自识别结果。
- **FAQ**：
  - 不知道文件类型也能转换吗？→ 可以。工具读取解码后内容的文件头判断类型，与文件名无关。
  - 转出来的文件打不开？→ 通常是 Base64 数据被截断或损坏。查看诊断面板中的错误提示，长度 % 4 余 1 说明内容不完整。
  - 支持 data URL 前缀吗？→ 支持。data:image/png;base64,... 格式会自动去除前缀并记录 MIME 类型。

### 3. /file-to-base64/

- **meta 标题**：文件转 Base64 在线工具 - 拖放即用 - b64file
- **meta 描述**：拖放任意文件生成 Base64 字符串，可选 URL-safe 格式或 data URL 前缀。适合 API 对接、JSON 嵌入、前端内嵌资源。本地处理。
- **H1**：文件转 Base64 在线工具
- **首屏导语**：拖个文件进来，变成 Base64 拿走。三种格式可选：标准、URL-safe、带 data: 前缀的直接塞进网页就能用。截图党福利：Ctrl+V 粘贴截图立即出结果。
- **章节「什么时候需要文件转 Base64」**：
  - API 对接 — 接口要求在 JSON 字段中传文件内容
  - 前端内嵌 — 小图片直接写进 HTML / CSS，减少请求数
  - 邮件与配置 — 在纯文本协议中携带二进制数据
- **章节「三种输出格式」**：
  - 标准 Base64 — 含 + / 和 =，最通用
  - URL-safe — - _ 替代，无填充，适合 URL 参数
  - data URL — 带 data:MIME;base64, 前缀，可直接放进 src
- **FAQ**：
  - 编码后体积会变多大？→ Base64 编码后体积约为原文件的 4/3（膨胀约 33%）。
  - 能批量转换吗？→ 当前版本一次一个文件。批量需求较多时会考虑加入。
  - 文件会上传吗？→ 不会，编码在浏览器本地完成，关闭页面后数据即消失。

### 8. /base64-decode-errors/

- **meta 标题**：Base64 解码失败常见原因与自动修复方法 - b64file
- **meta 描述**：Base64 解码报错的 5 大原因：非法字符、填充符错误、数据截断、Base64URL 混用、Data URL 前缀。附自动修复方案。
- **H1**：Base64 解码失败常见原因与修复方法
- **首屏导语**：解码失败不是玄学，八成是这五种之一。其中四类贴进工具就自动修好；第五种（数据截断）修不了——但工具会明确告诉你断在哪，省得瞎猜。
- **章节「1. 非法字符」**：Base64 标准字母表只含 A-Z、a-z、0-9、+、/ 和填充符 =。中文、全角空格、中文标点或二进制垃圾混入都会导致失败。修复：删除非法字符，或使用本站工具自动定位错误位置。
- **章节「2. 填充符缺失或多余」**：Base64 长度必须是 4 的倍数，不足时以 = 补齐（最多 2 个）。手工复制常丢失末尾的 =。修复：Base64 转文件工具自动补齐缺失填充、修正多余填充。
- **章节「3. 数据被截断（长度 % 4 余 1）」**：当去除填充后的长度除以 4 余 1 时，数据一定不完整——这种余数在任何合法 Base64 中都不存在。修复：无法自动恢复，需重新获取完整数据。
- **章节「4. Base64URL 与标准字母表混用」**：URL-safe 变体用 - _ 替代 + / 且通常省略填充。JWT 等场景常见。修复：本站工具检测到这两种字符时自动转换为标准字母表。
- **章节「5. Data URL 前缀未去除」**：data:image/png;base64, 这类前缀不是 Base64 的一部分，直接解码会报非法字符。修复：转换工具自动去除前缀并记录 MIME 类型。
- **FAQ**：
  - 长度 % 4 余 1 一定错吗？→ 是。合法 Base64 去除填充后长度除以 4 只能余 0、2 或 3，余 1 必然意味着数据不完整。
  - 解码成功但文件打不开？→ 内容可能不是你预期的格式，或原始文件本身损坏。查看结果卡片中识别出的文件类型。
  - 有自动修复工具吗？→ 本站 Base64 转文件工具内置上述全部自动修复逻辑，粘贴即可查看诊断报告。

## 已发现的口径不一致（统一时优先看）

1. **测试数两处口径**：页脚状态栏「67 tests」 vs 关于页「60+ 自动化测试」。
2. **同一勾选框两种叫法**：实际控件文字是「附加 data: MIME 前缀」（工具卡片），但 /image-to-base64/ FAQ 里写的是「勾选『加 data: 前缀』」。
3. **体积膨胀三种说法**：「约 33%」（file-to-base64、image-to-base64）、「约 1/3」（image-to-base64 导语）、「约 1.33 倍」（pdf-to-base64 两处）。
4. **大文件确认两处说法**：拖拽区小字「100 MB 封顶」+ 弹窗「占用较多浏览器内存，继续吗」 vs 首页 FAQ「超过 20 MB 会先跟你确认」。数字一致，措辞角度不同。
5. **邮箱出现三处**：页脚「反馈 greedy2899@gmail.com」、关于页「邮件至 …，每封都会读」、条款页「请联系 …」。
