## 一、项目是什么

b64file（https://b64file.cn）——Base64 ⇄ 文件的本地转换工具站。技术事实：纯静态前端 + 浏览器本地计算，服务器只发页面。**文案口径（2026-10-08 用户拍板）：不写「没有上传接口 / 不看你数据」这类自证式承诺**（像在辩解、不像开发者口吻），只陈述机制（「服务器只有静态文件，处理在浏览器里完成」）；顶栏绿色徽章保留，文案为「无需登录」。Claude Code 赤陶配色 + 像素终端风视觉，说人话的文案。变现目标：百度 SEO 流量 → 后续广告/增值。

- 代码：`D:\b64file`，git 仓库 `github.com/rie2899/b64file`（**private**），分支 main
- 技术栈：Vite + TypeScript（无框架），89 项 vitest 测试（含 happy-dom DOM 测试）
- 线上：腾讯云轻量服务器 + Docker nginx，IP `82.157.202.200`

## 二·五、2026-10-08 全站改造（本轮）

- **文案口径**：删除全部自证式隐私话术（「没有上传接口 / 不出浏览器 / Network 面板自证」），只陈述机制；顶栏绿色徽章保留，文案「无需登录」。删掉 8 条「会上传吗」类 FAQ。
- **新增页面**（14 → 22）：`base64-to-text` / `base64-to-pptx` / `base64url` / `base64-to-svg` / `base64-to-mp3` / `base64-to-txt` / `data-url` / `jwt-decode`。
- **新功能**：文本模式 URL-safe 输出、JWT 解码（三段式 token → header/payload 明文）、空态「载入示例」、Ctrl+Enter/Esc 快捷键、MIME 76 字符换行、大输入进度反馈。
- **百度主动推送（2026-10-09 恢复可用）**：`~/.hermes/scripts/baidu_push.sh <url>...`（token 从 `~/.hermes/notes/b64file-secrets.md` 读，**不进仓库、不进聊天**）。每日配额约 **10 条**，响应里 `remain` 是余量；配额用尽会返回 `{"error":400,"message":"over quota"}`（曾连续多日为 0，2026-10-09 恢复，当天已推 9 条：5 个新长尾页 + 4 个主工具页）。
  - 百度侧的实测状态（2026-10-09）：Baiduspider 近 30 天 **22 次**、最后一次 **9/27**（12 天零抓取）；对照组 Googlebot 7164、bingbot 71 —— 日志没问题，是百度不来。
  - **但站点在百度是有排名的**：近 90 天 `baidu.com/link` referer **63 次，全部落在首页 `/`**，搜索词集中在 `base64转文件` / `base64在线转文件` / `在线pdfbase64转文件`。说明没被惩罚，只是不抓新页、长尾页一个词都没排上。
  - **5 个新长尾页（svg/mp3/txt/data-url/jwt-decode）百度抓取次数 = 0** —— 这才是"新页没收录"的直接原因。
  - 百度没有等价的即时收录协议（IndexNow 只有必应/Yandex 系），只能：主动推送 API（配额内）+ 平台手动「抓取诊断」+ 持续出新内容。
- **GEO**：构建时自动生成 `llms.txt`（`vite.config.ts` 的 closeBundle 钩子）；正文加 RFC 4648 / MDN 权威外链。

- **IndexNow（必应即时收录，2026-10-09 配好）**：`public/<key>.txt` 放 32 位十六进制 key（内容必须等于文件名，否则必应校验不过），推送脚本 `bash scripts/indexnow.sh [url...]`，默认推 `dist/sitemap.xml` 全部 URL。**端点走 `https://www.bing.com/indexnow`** —— 实测本机代理节点到 `api.indexnow.net` 的 TLS 握手会被挡（`SSL_ERROR_SYSCALL`），必应入口通；可用 `INDEXNOW_ENDPOINT` 覆盖。**发新页后跑一次**，实测必应 1 分钟内就来取 key 文件（2026-10-09 01:54 UTC，bingbot 52.167.144.199）。
  - 坑一：key 文件不能用 `[A-Za-z0-9-]{8,128}` 通配去认 —— 构建产物 `baidu-urls.txt` 恰好满足那个字符集，会被误抓成 key（第一次推送就推了个假的 keyLocation）。按 **32 位十六进制**认。
  - 坑二：`pnpm build | tail` 会吃掉退出码，构建失败也会拿着旧 dist 继续跑；同理 `bash scripts/indexnow.sh | tail` 会把脚本的失败藏掉。两边都要看具体输出（HTTP 码）。
  - robots.txt 里 `Disallow: /baidu-urls.txt`（那是给百度 API 读的清单，不是内容页）。
- **相关链接**：原来全站铺 16 条同一份清单 → 改为按关系分组、每页 ≤5 条（分组表在 `static-pages.ts` 的 `PAGE_GROUP`）。
- **样式**：nav 与 main 都用 860px 容器（左边缘对齐）；≤900px 导航单行横向滚动；自托管 JetBrains Mono（`public/fonts/`，拉丁子集）。
- **测试计数**：89（页脚 statusbar 和关于页两处都会显示，改动后记得同步）。
### 内链图（2026-10-08 二次改造）

- **规则**：`relatedLinks()` 走一条**环**（`RELATED_RING`，按 decode → text → encode → guide → home → info 排序），每页取环上后 5 个。出链固定 ≤5（不铺清单），**入链恒为 5**（每页恰好被环上前 5 个页面链接到）。
- **为什么改**：旧实现是"取组内前 N 个"，排在组尾的页面永远吃不到入链 —— 实测有 5 页只有 2–3 条入链（`jwt-decode` / `base64url` / `image-to-base64` / `pdf-to-base64` / `json-to-file`）。加页时这个坑会重现。
- **不变量由测试守住**：`tests/pages.test.ts` 的"内链图"用例会渲染全部对外页面、统计出入链，任一页入链 <5 或出链 >5 直接测试失败。**加新页时若失败，调环的顺序而不是改测试。**
- **意图归属（防自相残杀）**：新页一律**不要在标题里写别人家的意图词**。已发生的例子：`base64url` 标题原带"（含 JWT）"，会跟专用的 `/jwt-decode/` 抢同一批查询 → 已把标题里的 JWT 让出去，正文与 FAQ 改成指向 `/jwt-decode/`，并从 jwt-decode 正文链回。
- **TDK 改动的安全边界**：查收录（`site:b64file.cn`）——**未进索引的新页可以改标题**，已被收录的页不动（用户的硬规则）。


## 二·八、服务器日志与 180 天留存（2026-10-09 配好）

- **日志落盘**：nginx 的 `access.log` / `error.log` 写到宿主机 `/data/b64file/logs/`（容器里挂载为 `/var/log/nginx`）。配置在 `deploy/nginx.conf` 顶部 + `deploy/docker-compose.yml` 的 `./logs:/var/log/nginx`。
- **轮转规则**：服务器上 `/etc/logrotate.d/b64file-nginx`（仓库副本 `deploy/logrotate-b64file-nginx`）—— `daily` + **`rotate 180`** + `compress` + `copytruncate` + `dateext`，满足公安备案「网络日志留存不少于 180 天」。用 `copytruncate` 是因为 nginx 在容器里持有句柄、logrotate 发不了重开信号。
- **⚠️ 查日志的位置变了**：改成文件日志后 `docker logs b64file-nginx` **只有启动信息，不再有访问记录**。所有蜘蛛/点击统计一律走文件：
  ```bash
  sudo -n grep -i baiduspider /data/b64file/logs/access.log* | wc -l          # 含历史轮转文件
  sudo -n grep -c 'baidu.com/link' /data/b64file/logs/access.log*            # 百度真实点击
  sudo -n sh -c "zcat -f /data/b64file/logs/access.log* | grep -i googlebot | wc -l"   # 被压缩的也能一起查
  ```
- **核查/导出留存**：`sudo -n ls /data/b64file/logs/` 看有哪些天；要给网安导出就 `tar czf b64file-logs-$(date +%F).tar.gz /data/b64file/logs/`。
- **演练记录**（2026-10-09）：`logrotate -d` 显示 `after 1 days (180 rotations)`；`logrotate -f` 生成了 `access.log-20261009`、原文件截断后继续写入 ✓。
- **残留风险**：这台机器上其它容器（xianyu-assistant / pet-manager / article-tools）仍是 `json-file` 无轮转 —— 如果网安的核查范围包含它们，要单独处理（改 Docker 全局 `log-opts` 需重启 Docker，会把这台机器上所有容器一起重启，务必挑时间）。
- 备份：改动前的原始配置留在服务器 `nginx.conf.bak-20261009-1126` / `docker-compose.yml.bak-20261009-1126`。
